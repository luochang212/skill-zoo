# desktop-ui Specification

## Purpose

定义 Tauri 桌面界面（`src/`）的交互与可达性契约：折叠与展开控件必须向辅助技术暴露状态且不得留下不可见却可聚焦的内容，位移动画必须真正作用于发生变化的属性，主题必须能在应用任意位置跟随操作系统且不出现错误的原生配色，共享表单控件必须提供可见的键盘焦点指示与可访问名称，键盘提交必须对输入法合成安全。

## Requirements

### Requirement: 折叠控件的状态与可聚焦性

可折叠区域的开关控件 MUST 通过 `aria-expanded` 暴露当前展开状态。处于折叠状态时，其内部的可交互内容 MUST NOT 保留在 Tab 序列或无键树中；实现 MUST NOT 依靠零高度、零不透明度或裁剪来"隐藏"仍参与聚焦的子项。

#### Scenario: 折叠后内容不可聚焦
- **WHEN** 用户将侧栏的仓库分组折叠
- **THEN** 该分组内的仓库与未分配按钮不再出现于文档中，键盘与读屏均无法到达
- **AND** 开关报告的展开状态为 `false`

#### Scenario: 展开后内容恢复可交互
- **WHEN** 用户再次展开该分组
- **THEN** 分组内的条目重新渲染并可正常聚焦与点击
- **AND** 开关报告的展开状态为 `true`

#### Scenario: 展开态内容不被上限裁剪
- **WHEN** 分组内的条目总高度超过一屏（例如仓库数量很多）
- **THEN** 所有条目均可完整显示并可达，不存在被静默截断的条目

#### Scenario: 文件树目录暴露展开状态
- **WHEN** 文件树中的某个目录处于展开或折叠状态
- **THEN** 该目录按钮通过 `aria-expanded` 报告对应状态
- **AND** 文件（非目录）条目不报告展开状态

### Requirement: 位移动画作用于实际变化的属性

当界面元素以位移方式出现或消失时，其过渡 MUST 作用于实际被改变的属性。声明了过渡但实际位移瞬时跳变（只淡入或只淡出） MUST 被视为缺陷。

#### Scenario: 侧栏滑入伴随位移
- **WHEN** 用户展开技能详情页的文件树侧栏
- **THEN** 侧栏在位移动画中从左侧滑入，而非原地淡入

#### Scenario: 侧栏滑出伴随位移
- **WHEN** 用户折叠该侧栏
- **THEN** 侧栏在位移动画中向左滑出

### Requirement: 主题跟随系统

当用户的主题设置为"跟随系统"时，操作系统深浅色偏好的变化 MUST 在应用的任意视图中立即生效，而不限于设置视图处于挂载状态时。监听 MUST 在事件发生时重新读取当前主题设置，以显式的"浅色"或"深色"选择 MUST NOT 被系统偏好变化覆盖。

#### Scenario: 非设置视图下跟随系统
- **WHEN** 主题设置为"跟随系统"，且用户停留在技能列表或详情视图
- **AND** 操作系统切换深浅色偏好
- **THEN** 应用界面立即切换到对应的配色

#### Scenario: 显式选择不被系统变化覆盖
- **WHEN** 用户显式选择了"浅色"或"深色"
- **AND** 操作系统切换深浅色偏好
- **THEN** 应用保持用户选择的配色不变

#### Scenario: 设置视图内仍然生效
- **WHEN** 主题设置为"跟随系统"且用户停留在设置视图
- **AND** 操作系统切换深浅色偏好
- **THEN** 应用界面立即切换到对应的配色

### Requirement: 原生配色与主题一致

根元素的默认 `color-scheme` MUST 允许深浅两种取值，不得在不反映用户选择的情况下钉死为单一方案。当主题为"跟随系统"时，原生控件与滚动条 MUST 由系统偏好决定。

#### Scenario: 跟随系统时的原生配色
- **WHEN** 主题为"跟随系统"且应用尚未完成脚本化主题应用
- **THEN** 原生控件与滚动条按系统偏好渲染，不出现深色页面配浅色原生控件

#### Scenario: 显式主题仍被钉住
- **WHEN** 用户显式选择"深色"
- **THEN** 原生控件与滚动条呈深色，不受系统偏好影响

### Requirement: 主题切换不出现错误配色

主题切换的视觉过渡 MUST NOT 在过渡过程中展示切换前的配色。过渡结束时的可见配色 MUST 与用户选择一致。

#### Scenario: 过渡展示新配色
- **WHEN** 用户触发主题切换（含圆形展开过渡）
- **THEN** 过渡过程中呈现的是新主题配色，不出现旧配色先展开再跳变

### Requirement: 表单控件的焦点可见性

共享输入控件 MUST 在键盘聚焦时提供可感知的焦点指示。实现 MUST NOT 仅移除默认轮廓而不提供替代指示。焦点指示与该控件未聚焦时的呈现 MUST 达到不低于 3:1 的对比度（WCAG 1.4.11 非文本对比）。输入控件 MUST 沿用"边框颜色变化"这一既有视觉语言，不得改为绘制描边环。

#### Scenario: 键盘聚焦输入框可见
- **WHEN** 用户用 Tab 聚焦到共享输入框或列表搜索框
- **THEN** 呈现出与其未聚焦状态对比不低于 3:1 的焦点指示

#### Scenario: 焦点指示沿用边框语言
- **WHEN** 输入控件获得键盘焦点
- **THEN** 指示以边框颜色变化呈现，不绘制额外的描边环

### Requirement: 可访问名称

交互控件的可访问名称 MUST 不依赖占位符文本。列表行上的选择控件 MUST 提供可区分当前行对象的名称。

#### Scenario: 行选择复选框有名称
- **WHEN** 读屏聚焦到技能列表某行的选择复选框
- **THEN** 播报的名称包含该行对应的技能标识，而非仅有"复选框"

#### Scenario: 全选复选框有名称
- **WHEN** 读屏聚焦到列表的全选复选框
- **THEN** 播报一个说明其全选语义的名称

#### Scenario: 搜索框有名称
- **WHEN** 读屏聚焦到列表搜索框
- **THEN** 播报的名称来自可访问名称属性，而非来自占位符

### Requirement: 键盘提交对输入法安全

文本输入框上的键盘提交 MUST 在输入法合成（IME composition）期间被抑制。在合成候选词确认时按下的回车键 MUST NOT 触发提交、导航或清空输入等副作用。

#### Scenario: 合成期间回车不提交
- **WHEN** 中文输入法正在合成候选词，用户按回车确认候选
- **THEN** 不发生搜索导航或输入清空，合成正常结束

#### Scenario: 合成结束后回车正常提交
- **WHEN** 输入法合成已结束，用户按回车
- **THEN** 提交按既有行为正常发生
