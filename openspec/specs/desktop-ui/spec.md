# desktop-ui Specification

## Purpose

定义 Tauri 桌面界面（`src/`）的交互与可达性契约：折叠与展开控件必须向辅助技术暴露状态且不得留下不可见却可聚焦的内容，位移动画必须真正作用于发生变化的属性，主题必须能在应用任意位置跟随操作系统且不出现错误的原生配色，共享表单控件必须提供可见的键盘焦点指示与可访问名称，键盘提交必须对输入法合成安全。

## Requirements

### Requirement: 折叠控件的状态与可聚焦性

可折叠区域的开关控件 MUST 通过 `aria-expanded` 暴露当前展开状态。处于折叠状态时，其内部的可交互内容 MUST NOT 保留在 Tab 序列或无键树中；实现 MUST NOT 依靠零高度、零不透明度或裁剪来"隐藏"仍参与聚焦的子项。

#### Scenario: 折叠后内容不可聚焦
- **WHEN** 用户将侧栏的仓库分组折叠
- **THEN** 该分组内的仓库与未分配按钮不再出现于文档中，键盘与读屏均无法到达
- **AND** 开关报告的展开状态为 `false`

#### Scenario: 展开后内容恢复可交互
- **WHEN** 用户再次展开该分组
- **THEN** 分组内的条目重新渲染并可正常聚焦与点击
- **AND** 开关报告的展开状态为 `true`

#### Scenario: 展开态内容不被上限裁剪
- **WHEN** 分组内的条目总高度超过一屏（例如仓库数量很多）
- **THEN** 所有条目均可完整显示并可达，不存在被静默截断的条目

#### Scenario: 文件树目录暴露展开状态
- **WHEN** 文件树中的某个目录处于展开或折叠状态
- **THEN** 该目录按钮通过 `aria-expanded` 报告对应状态
- **AND** 文件（非目录）条目不报告展开状态

#### Scenario: 技能文件侧栏收起后退出焦点序列
- **WHEN** 用户收起技能详情页的文件侧栏
- **THEN** 侧栏内的文件树不再保留在 Tab 序列与无障碍树中
- **AND** 若收起时焦点位于侧栏内部，焦点移动到可见的侧栏开关控件

### Requirement: 位移动画作用于实际变化的属性

当界面元素以位移方式出现或消失时，其过渡 MUST 作用于实际被改变的属性。声明了过渡但实际位移瞬时跳变（只淡入或只淡出） MUST 被视为缺陷。

#### Scenario: 侧栏滑入伴随位移
- **WHEN** 用户展开技能详情页的文件树侧栏
- **THEN** 侧栏在位移动画中从左侧滑入，而非原地淡入

#### Scenario: 侧栏滑出伴随位移
- **WHEN** 用户折叠该侧栏
- **THEN** 侧栏在位移动画中向左滑出

### Requirement: 主题跟随系统

当用户的主题设置为"跟随系统"时，操作系统深浅色偏好的变化 MUST 在应用的任意视图中立即生效，而不限于设置视图处于挂载状态时。监听 MUST 在事件发生时重新读取当前主题设置，以显式的"浅色"或"深色"选择 MUST NOT 被系统偏好变化覆盖。

#### Scenario: 非设置视图下跟随系统
- **WHEN** 主题设置为"跟随系统"，且用户停留在技能列表或详情视图
- **AND** 操作系统切换深浅色偏好
- **THEN** 应用界面立即切换到对应的配色

#### Scenario: 显式选择不被系统变化覆盖
- **WHEN** 用户显式选择了"浅色"或"深色"
- **AND** 操作系统切换深浅色偏好
- **THEN** 应用保持用户选择的配色不变

#### Scenario: 设置视图内仍然生效
- **WHEN** 主题设置为"跟随系统"且用户停留在设置视图
- **AND** 操作系统切换深浅色偏好
- **THEN** 应用界面立即切换到对应的配色

### Requirement: 原生配色与主题一致

根元素的默认 `color-scheme` MUST 允许深浅两种取值，不得在不反映用户选择的情况下钉死为单一方案。当主题为"跟随系统"时，原生控件与滚动条 MUST 由系统偏好决定。

#### Scenario: 跟随系统时的原生配色
- **WHEN** 主题为"跟随系统"且应用尚未完成脚本化主题应用
- **THEN** 原生控件与滚动条按系统偏好渲染，不出现深色页面配浅色原生控件

#### Scenario: 显式主题仍被钉住
- **WHEN** 用户显式选择"深色"
- **THEN** 原生控件与滚动条呈深色，不受系统偏好影响

### Requirement: 主题切换不出现错误配色

主题切换的视觉过渡 MUST NOT 在过渡过程中展示切换前的配色。过渡结束时的可见配色 MUST 与用户选择一致。

#### Scenario: 过渡展示新配色
- **WHEN** 用户触发主题切换（含圆形展开过渡）
- **THEN** 过渡过程中呈现的是新主题配色，不出现旧配色先展开再跳变

### Requirement: 表单控件的焦点可见性

共享输入控件 MUST 在键盘聚焦时提供可感知的焦点指示。实现 MUST NOT 仅移除默认轮廓而不提供替代指示。焦点指示与该控件未聚焦时的呈现 MUST 达到不低于 3:1 的对比度（WCAG 1.4.11 非文本对比）。输入控件 MUST 沿用"边框颜色变化"这一既有视觉语言，不得改为绘制描边环。

#### Scenario: 键盘聚焦输入框可见
- **WHEN** 用户用 Tab 聚焦到共享输入框或列表搜索框
- **THEN** 呈现出与其未聚焦状态对比不低于 3:1 的焦点指示

#### Scenario: 焦点指示沿用边框语言
- **WHEN** 输入控件获得键盘焦点
- **THEN** 指示以边框颜色变化呈现，不绘制额外的描边环

### Requirement: 可访问名称

交互控件的可访问名称 MUST 不依赖占位符文本。列表行上的选择控件 MUST 提供可区分当前行对象的名称。

#### Scenario: 行选择复选框有名称
- **WHEN** 读屏聚焦到技能列表某行的选择复选框
- **THEN** 播报的名称包含该行对应的技能标识，而非仅有"复选框"

#### Scenario: 全选复选框有名称
- **WHEN** 读屏聚焦到列表的全选复选框
- **THEN** 播报一个说明其全选语义的名称

#### Scenario: 搜索框有名称
- **WHEN** 读屏聚焦到列表搜索框
- **THEN** 播报的名称来自可访问名称属性，而非来自占位符

### Requirement: 键盘提交对输入法安全

文本输入框上的键盘提交 MUST 在输入法合成（IME composition）期间被抑制。在合成候选词确认时按下的回车键 MUST NOT 触发提交、导航或清空输入等副作用。

#### Scenario: 合成期间回车不提交
- **WHEN** 中文输入法正在合成候选词，用户按回车确认候选
- **THEN** 不发生搜索导航或输入清空，合成正常结束

#### Scenario: 合成结束后回车正常提交
- **WHEN** 输入法合成已结束，用户按回车
- **THEN** 提交按既有行为正常发生

### Requirement: 自定义技能浮层轻入场

技能信息与审计详情的自定义浮层 MUST 在普通运动偏好下使用短暂淡入和微小位移出现。动画 MUST NOT 增加打开延迟或改变定位、关闭规则。

#### Scenario: 打开小浮层
- **WHEN** 用户打开技能信息或审计详情浮层
- **THEN** 浮层以 140ms、3px 位移的轻入场显示，既有打开／关闭规则保持

### Requirement: 主操作按压反馈

安装入口、确认安装与编辑器保存按钮 MUST 在指针按住时提供 .98 缩放反馈，松开恢复。disabled 按钮 MUST NOT 触发按压缩放。反馈 MUST NOT 改变业务动作或影响拖拽宿主。

#### Scenario: 按住安装或保存
- **WHEN** 用户按住可用的安装或保存按钮
- **THEN** 按钮轻微缩小，松开恢复，业务仍按既有点击规则执行

#### Scenario: disabled 按钮
- **WHEN** 安装或保存按钮不可用
- **THEN** 按住不触发缩放或业务动作

### Requirement: 系统减少动态效果

当系统 `prefers-reduced-motion` 为 reduce 时，页面与仓库预览侧面板 MUST 直接显示最终状态，轮播 MUST 停止自动播放且手动切换 MUST 不播放过渡；自定义浮层、主操作按压、折叠布局与共享菜单／对话框 MUST 静态降级。偏好运行中改变时 MUST 清理轮播旧 timer，静态加载标识与操作入口 MUST 保留。

#### Scenario: 减少动态效果下浏览
- **WHEN** 系统偏好为 reduce，用户切换页面、打开侧面板或小浮层
- **THEN** 内容直接显示，不播放入场／位移过渡；按钮不缩放

#### Scenario: 偏好改变清理自动播放
- **WHEN** 轮播正在自动播放，系统偏好变为 reduce
- **THEN** 旧 timer 被清理，当前条目保持；手动切换仍可用且无过渡

#### Scenario: 恢复普通运动偏好
- **WHEN** 系统偏好恢复普通，轮播未悬停且有多个条目
- **THEN** 按既有 8 秒周期恢复自动播放，不留下重复 timer

### Requirement: 更新管理弹窗可关闭且更新继续

更新管理弹窗 MUST 在检查、更新与历史操作期间支持关闭按钮、Esc 和外部点击关闭。关闭或离开设置页 MUST NOT 中断已开始的更新；重新打开 MUST 反映全局更新状态及持久化历史。

#### Scenario: 更新期间关闭并重新打开
- **WHEN** 更新尚未结束，用户通过任一关闭入口关闭弹窗并重新打开
- **THEN** 更新继续执行，弹窗仍显示更新进行中并阻止重复更新

#### Scenario: 离开设置页后更新完成
- **WHEN** 用户离开设置页且后台更新完成后返回更新管理
- **THEN** 更新状态恢复空闲，列表和历史从当前数据读取

### Requirement: 后台批量更新结果通知

应用 MUST 为每次批量或所选更新的最终结果显示一次本地化通知，无论设置页是否挂载。通知 MUST 区分成功、部分失败、全部失败、因本地修改跳过和无需更新，失败时提供可读原因，跳过时列出技能；命令拒绝 MUST 只显示一次错误通知。

#### Scenario: 后台完成
- **WHEN** 用户已关闭更新管理或离开设置页，更新结束
- **THEN** 通知概括更新结果，部分或全部失败时给出成功与失败数量并带有原因

#### Scenario: 重复缓存事件
- **WHEN** 同一次更新结算后缓存发生其他通知或监听组件重新挂载
- **THEN** 不再次提示旧结果

#### Scenario: 没有需要更新的技能
- **WHEN** 更新完成且成功与失败数量均为零且没有因本地修改跳过的技能
- **THEN** 显示无需更新的提示而非失败


#### Scenario: 离开设置页后仍报告跳过
- **WHEN** 用户离开设置页后更新结束且有因本地修改跳过的技能
- **THEN** 同一条结果通知列出跳过的技能并保留成功或失败摘要，不把跳过解释为全部最新

### Requirement: 并发写操作冲突友好报错

安装、单个更新、全部或所选更新、删除命令遭遇已占用写操作租约时 MUST 返回稳定错误码 `operationInProgress`。界面 MUST 显示当前语言的稍后重试提示，不展示原始租约报错。其他租约建立失败 MUST 保留原错误分类，不伪装成并发操作。

#### Scenario: 更新时删除或安装
- **WHEN** 更新占用写操作租约，用户删除或安装技能
- **THEN** 命令立即失败，显示友好的稍后重试提示，已有更新继续

### Requirement: 后台更新退出确认

真实退出入口在批量或所选更新命令存活时 MUST 要求确认，取消 MUST 保留窗口与任务，重复退出请求 MUST NOT 堆叠确认。窗口关闭与托盘退出 MUST 覆盖；macOS 系统 Cmd+Q 与 Dock 退出受当前原生框架限制，不保证确认。没有后台更新时 MUST 保留既有退出行为。

#### Scenario: 更新中关闭窗口或托盘退出
- **WHEN** 用户在后台更新期间关闭主窗口或选择托盘退出
- **THEN** 显示本地化退出确认，取消后窗口与更新仍存活，确认后退出

#### Scenario: 未更新或任务结束
- **WHEN** 没有后台批量更新，用户请求退出
- **THEN** 无更新确认，按既有行为退出

### Requirement: 编辑器保存与草稿保护

技能编辑器的保存完成 MUST 只确认当次提交的内容修订：保存请求在途期间用户继续输入的新内容 MUST 保留为未保存草稿，不得被保存完成或随后的内容重置覆盖。辅助文件（非 SKILL.md）的未保存草稿 MUST 按文件保留，切换其他文件不得丢弃；当存在未保存草稿或未保存的 SKILL.md 修改时，切换技能与关闭详情 MUST 先经用户确认，归档入口 MUST 禁用并说明原因。

#### Scenario: 保存期间输入不被覆盖
- **WHEN** 保存请求在途时用户继续编辑出内容 B，随后保存以提交时的内容 A 成功
- **THEN** 编辑器仍显示 B 且处于未保存状态，不回退为 A

#### Scenario: 无新输入时保存正常收尾
- **WHEN** 保存请求在途期间用户未再输入，保存成功
- **THEN** 编辑器未保存状态清除

#### Scenario: 切换文件保留各文件草稿
- **WHEN** 用户在 README.md 中有未保存草稿，切到 SKILL.md 再切回 README.md
- **THEN** README.md 的草稿原样恢复，且父级收到存在未保存草稿的报告

#### Scenario: 关闭详情前确认未保存内容
- **WHEN** 存在未保存的 SKILL.md 修改或辅助文件草稿时用户关闭详情
- **THEN** 出现确认对话框，用户取消则留在编辑器，确认丢弃则关闭

#### Scenario: 存在未保存内容时归档被禁用
- **WHEN** 存在未保存的 SKILL.md 修改或辅助文件草稿
- **THEN** 归档入口禁用并提示先保存或丢弃修改

#### Scenario: 迟到保存不能确认新会话
- **WHEN** 用户关闭在途保存的详情并打开同一或另一技能，随后旧保存完成
- **THEN** 新会话的草稿及未保存状态不受影响，即使文本相同

#### Scenario: 同目录不同技能隔离辅助草稿
- **WHEN** 用户确认丢弃草稿并切换至 directory 相同但身份不同的技能
- **THEN** 原技能草稿不出现在新技能内，旧请求不能清除新技能草稿

#### Scenario: 还原已保存正文
- **WHEN** 用户把辅助文件改回已保存正文且没有会改变该文件基线的在途保存
- **THEN** 该文件不再被视为未保存，不单独阻止归档或触发离开确认

#### Scenario: 保存期间撤销回旧正文
- **WHEN** 保存内容 A 在途，用户编辑回先前磁盘正文 B，随后 A 保存成功
- **THEN** B 仍作为未保存草稿保留，直到用户保存或明确丢弃

### Requirement: 应用更新状态不被过时响应倒退

应用更新流程中的异步响应 MUST 按请求代次丢弃过时结果：启动时的后台更新检查与用户手动流程共享同一协调规则，迟到的过时响应 MUST NOT 将 downloading 或 readyToRestart 状态倒退为 idle 或 available，也 MUST NOT 清除已就绪的更新版本。

#### Scenario: 迟到的启动检查不重置已下载完成状态
- **WHEN** 启动时的后台检查尚未返回，用户已手动完成下载进入 readyToRestart，随后启动检查返回"无更新"
- **THEN** 状态保持 readyToRestart 且重启入口可用
