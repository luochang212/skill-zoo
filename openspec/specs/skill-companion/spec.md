# skill-companion Specification

## Purpose

承载常用指令(Skill Companion)条目的转移契约:导出把条目列表序列化为带版本信封的 JSON 文本写入剪贴板,导入解析同一格式、按空白归一化去重并只追加合并。条目的日常增删改、排序与托盘点击复制为既有行为,不属于本规范。

## Requirements

### Requirement: 导出为带版本信封的剪贴板文本

用户在常用指令管理弹窗发起导出时,系统 MUST 将当前已保存的条目内容序列化为 JSON 信封文本并写入系统剪贴板。信封 MUST 包含标识字段 `kind: "skill-zoo-companion"`、整数版本号 `version` 与条目内容字符串数组 `items`;信封 MUST NOT 包含条目本地 id。序列化 MUST 保证任意字符(包括引号、反斜杠、`$`、`@`、`/`、换行与中文)无损往返。导出成功与失败 MUST 以 toast 反馈,成功文案携带导出条数;列表为空时导出动作 MUST 不可用。

#### Scenario: 含特殊字符与多行的条目无损导出

- **WHEN** 用户导出包含引号、反斜杠、`$`、`@`、`/`、换行或中文字符的条目列表
- **THEN** 剪贴板中的文本是合法的 JSON 信封,且经本应用导入后每条内容与导出前完全一致

#### Scenario: 导出成功反馈条数

- **WHEN** 用户导出 8 条指令成功
- **THEN** 应用展示成功 toast,文案包含导出条数 8

#### Scenario: 空列表不可导出

- **WHEN** 常用指令列表为空
- **THEN** 导出动作处于不可用状态,不产生剪贴板写入

### Requirement: 导入解析同一信封格式并拒绝无关文本

导入 MUST 只接受本应用导出的信封格式:解析 JSON、校验 `kind` 与 `version`、接受 `items` 字符串数组,并丢弃 trim 后为空的条目。解析或校验失败时,系统 MUST 以 toast 给出明确的失败原因,且 MUST NOT 改变现有条目列表。

#### Scenario: 粘贴有效导出文本

- **WHEN** 用户在导入对话框粘贴本应用导出的信封文本并确认
- **THEN** 文本被解析为条目内容列表,进入去重合并流程

#### Scenario: 粘贴无关文本被拒绝

- **WHEN** 用户粘贴的不是本应用导出的文本(非法 JSON、缺少或错误的 `kind`/`version`、`items` 类型不符)
- **THEN** 应用展示失败 toast 并说明原因,现有条目列表保持不变

### Requirement: 导入按空白归一化去重并只追加

导入合并 MUST 以条目内容为键(连续空白折叠为单空格并去除首尾空白后比较),先在导入内容内部去重,再与现有列表去重;未命中的条目 MUST 按导入顺序追加到列表尾部并重新生成 id,现有条目的内容、id 与顺序 MUST 保持不变。导入结果 MUST 以 toast 报告导入条数与跳过的重复条数。

#### Scenario: 与现有列表重复的条目被跳过

- **WHEN** 导入文本中某条内容与现有某条在空白归一化后相同(如仅空格数量或换行差异)
- **THEN** 该条目被跳过,现有条目保持原样

#### Scenario: 导入内容内部重复只保留一条

- **WHEN** 导入文本内部含两条空白归一化后相同的内容
- **THEN** 仅导入其中一条

#### Scenario: 新条目追加且现有顺序不变

- **WHEN** 导入产生 3 条新条目,现有列表已有 5 条
- **THEN** 合并后列表共 8 条,前 5 条的内容、id 与顺序不变,新 3 条依次追加于尾部并拥有新生成的 id,toast 报告"导入 3 条"

#### Scenario: 全部重复时无新增

- **WHEN** 导入文本中所有条目均与现有列表重复
- **THEN** 列表不发生变化,toast 报告导入 0 条并注明全部为重复
