# Proposal

## Why

按 worth-fix 复核翻译自检报告，四项生产函数复现均属实。这里只修已有内容保护契约中的低成本缺口，不更换任务模型或引入完整 Markdown 解析器。

## What Changes

- 流式预览容忍 description 标记乱序与缺失，交给最终保真校验和既有修复处理。
- 代码围栏的关闭标记必须保持开启时的引用层级。
- 有头部的文档不接受前置说明或代码包装作为成功译文。
- 与阅读器对齐，保护带 BOM 或前导空白的头部；更新翻译缓存策略版本。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `skill-content-translation`: 预览容错与文档边界保真。

## Impact

仅影响 Rust 文档保护及测试、相关规格和派生缓存键；无新依赖，无 IPC 或持久化结构变化，不改技能源文件。

## Worth-fix assessment

| 报告 | 真实性与实际影响 | 触发概率与修复成本 | 决策 |
|---|---|---|---|
| 乱序标记 panic | 生产 preview 已复现切片 panic；最终校验之前中断。页面永久挂起和任务清理后果来自调用链审查，未实机确认 | 模型异常输出时可达，真实频率未知；限制搜索区间即可 | 修，P1 |
| 引用式围栏提前闭合 | 阅读器仍判为代码，保护层却暴露文本；修改文本后 restore 放行 | 含 Markdown 示例时可达，非所有代码块；补齐引用层级判断 | 修，P2 |
| 头部前置说明 | restore 放行但阅读器不展示元数据表；原字段文本仍在，不是源数据丢失 | 模型额外前言时可达，真实频率未知；一个位置约束 | 修，P2，收窄上一轮的影响描述 |
| BOM 头部 | 阅读器识别而后端不保护；模型可改 name 并通过 restore | 上轮 119 份本机样本无 BOM，属跨平台边界；规范化头部起点成本很低 | 修，低优先级，收益大于成本 |

前两次前后端探针调用生产函数及实际阅读器；本次把四个场景翻转为正确行为的回归断言，已观察到四红再四绿。不主张为这些局部缺陷重构整个翻译功能。
