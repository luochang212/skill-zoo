# Design

## Context

见 proposal.md 中四项 worth-fix 结论及验证边界。现有后台任务与 YAML 对象机制保留。

## Goals / Non-Goals

补齐已复现的保护缺口；不尝试重写 Markdown 语法、恢复模型任意前言，或更换事件与任务架构。

## Decisions

- description 结束标记只从开始标记之后搜索。乱序前缀不做危险切片，最终校验继续拒绝。
- 记录围栏开启时的引用深度，仅允许同深度关闭；与现有字符及长度检查共用。
- 记录是否存在头部，以其保护标记必须位于输出起点作为约束。拒绝而非猜测如何删除模型前言，避免误删正文。
- 读取头部起点时跳过 BOM/空白，原字段仍走 YAML 对象保护。升级缓存策略版本，旧缓存不自动重译。

## Risks / Trade-offs

模型多余前言现在会明确失败而非静默丢失元数据表。围栏扫描仍不是完整 CommonMark 解析器，引用容器提前结束等超出本次验证的语法不宣称解决；未来若真实样本跨过这一边界，再评估引入解析器的收益与依赖成本。
