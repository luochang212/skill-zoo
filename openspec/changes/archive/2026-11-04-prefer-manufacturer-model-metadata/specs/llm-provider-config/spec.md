## MODIFIED Requirements

### Requirement: 公开模型目录识别
智能识别 MUST 通过 Rust IPC 读取 Models.dev 的固定匿名 JSON 目录，MUST NOT 上传 API Key、请求头或文档。目录按内存 TTL 缓存，限定请求时限与响应体大小。匹配 MUST 优先服务地址及完整模型 ID，再尝试可可靠识别的原厂条目（完整 ID 优先于精确末段 ID）；原厂候选有效时采用。其余候选按完整 ID、精确末段 ID 分级，以有效「上下文窗口、最大输出」组合的众数选择；各优先级中并列众数（含各组合均只出现一次）MUST 按候选固定遍历顺序取第一个已有配置，无有效结果不回填，当前服务条目无效时不绕过。MUST NOT 使用子串或型号近似匹配，不改变请求地址或模型 ID；目录未收录或网络失败 MUST 保留手动编辑与确认。公开目录只提供参考，不验证模型在当前账号可用性。

#### Scenario: 自定义模型未识别
- **WHEN** 模型 ID 无可用匹配、候选均无有效推荐，或公开目录不可达
- **THEN** 静默保留手动填写与确认，不显示失败/未匹配提示或 toast，不改用其他模型

#### Scenario: 中转与命名空间模型
- **WHEN** 中转或 Coding Plan 地址未命中目录，但完整模型 ID 或去除命名空间后的精确 ID 有一致的推荐参数
- **THEN** 回填参数，实际地址与模型 ID 保持用户输入

#### Scenario: 优先级与候选冲突
- **WHEN** 当前服务有精确匹配，或兜底候选存在并列众数
- **THEN** 优先采用当前服务参数；并列时在当前匹配层取固定顺序的第一个有效配置，不从较低优先级选择其他值

#### Scenario: 原厂优先于中转差异
- **WHEN** 中转地址上的 qwen3.8-flash 候选参数不同，但阿里云原厂条目有一致有效的参数
- **THEN** 采用原厂参数，不因其他中转条目不同而放弃匹配

#### Scenario: 无可靠原厂时取众数并确定性处理并列
- **WHEN** 无可靠原厂推荐，候选限制组合出现次数分别为 2、1、1 或 2、2
- **THEN** 前者采用出现两次的组合，后者采用并列组合中固定顺序的第一个配置；不得分别对两个参数取众数拼出不存在的组合
