## MODIFIED Requirements

### Requirement: 状态与只读展示
下拉 MUST 提供翻译为当前目标语言、语言选择、翻译设置；有结果时提供原文/译文切换与重译，翻译按钮右侧在翻译及自动修复中显示中止按钮，终止失败后显示重试按钮，其余状态不显示；中止从下拉移至该按钮，按钮只显示图标，悬停提示和可访问名称保留动作文字。初次翻译等待首段正文时 MUST 保留可阅读原文，MUST NOT 用加载图标或空状态替换正文；收到正文后流式显示，允许查看原文；重译等待首段新正文时保留旧成功译文，收到非空预览后 MUST 渐进显示新译文；重译失败或取消 MUST 恢复旧成功译文，只有成功后才替换成功结果与磁盘缓存；用户在生成期间切回原文后，完成 MUST NOT 强制切回译文。译文通过按钮选中态与 tooltip 标识，无常驻模型/AI 文字。编辑或分屏 MUST 使用原文，任何译文 MUST NOT 进入原文草稿或保存路径。当前会话的任务与结果 MUST 保留；重新进入时的正文展示 MUST 遵循「优先显示译文」偏好。自动读取 MUST NOT 发起模型请求。

#### Scenario: 从译文进入编辑
- **WHEN** 用户在译文视图切到编辑
- **THEN** 编辑器仅显示原文，已有草稿保护继续生效

### Requirement: 取消与结果身份隔离
请求 MUST 在发起前拥有可取消的身份。离页或切换文件/技能 MUST 仅解除当前视图订阅，不取消已手动发起的翻译；同一应用会话内返回匹配技能、文件、源文、目标语言和有效模型配置时 MUST 接续进度或结果，不重复请求。源文、目标或配置不同的视图 MUST NOT 显示旧任务结果。显式取消或重译 MUST 使旧任务失效并忽略其迟到事件；取消 MUST NOT 报错或提交部分缓存。正常完成提交与取消 MUST 有唯一先后顺序，提交后取消不撤销成功缓存；不承诺供应商服务端停止生成或计费，也不承诺退出应用后恢复在途任务。

#### Scenario: 首块前离开
- **WHEN** 请求注册或发出后尚无首块时用户切换文件或离页
- **THEN** 原任务继续，新文件不展示原任务结果，返回原文件接续原任务而不重复发请求

#### Scenario: 离页期间完成
- **WHEN** 当前视图已卸载，手动翻译成功完成后用户返回相同身份的文件
- **THEN** 当前应用会话保留完成结果，不重复翻译；开启优先显示译文时按会话选择显示结果，关闭时先显示原文并允许手动查看已有译文

#### Scenario: 显式取消及重译
- **WHEN** 用户显式取消，或主动重译替换已有任务
- **THEN** 旧任务即使稍后注册成功或送达事件也不覆盖当前结果；重译保留旧成功译文作为失败或取消时的回退；首段新正文到达后渐进显示新译文

#### Scenario: 同一身份重复启动
- **WHEN** 同一任务正在进行，另一个视图或重复点击再次请求普通翻译
- **THEN** 共享已有任务，不重复发起模型请求

### Requirement: 缓存与重新翻译
缓存 MUST 由有效协议、规范化 URL、模型、输出参数、目标语言、源文及翻译策略版本决定，不含技能/文件 ID 或 API Key；同有效配置可共享。只在成功提交后原子写入应用缓存，MUST NOT 修改技能文件。重译 MUST 跳过旧缓存读取但保留旧条目至新结果成功。清空 MUST 先在原按钮将「清空」改为「确认」，再次激活才执行；确认状态 MUST 更醒目，且切换前后按钮形状与尺寸 MUST 保持一致。退出翻译设置后重新进入，以及一次清空操作结束后，按钮 MUST 恢复「清空」。清空 MUST 不影响其他数据，清空前已在途任务 MUST NOT 将结果写回缓存。

#### Scenario: 重译失败
- **WHEN** 缓存已有成功译文，用户重译失败
- **THEN** 旧译文和旧缓存仍可用

#### Scenario: 强制重译渐进显示
- **WHEN** 用户对已有成功译文（包括自动读取的缓存译文）选择重新翻译
- **THEN** 请求必须强制跳过旧缓存，不再次读取缓存或以旧缓存结束任务；首段非空新预览到达后逐步显示新译文，空预览不清空旧内容，最终成功后更新成功结果；失败或取消恢复旧成功译文与既有缓存

#### Scenario: 清空按钮二次确认
- **WHEN** 用户第一次激活清空按钮
- **THEN** 只将按钮文案改为确认，不清理缓存；再次激活才清空，退出重入时确认状态重置

#### Scenario: 清空时有在途请求
- **WHEN** 用户清空缓存后旧请求完成
- **THEN** 结果可供本次查看，但不会回填已清空的缓存

### Requirement: 单请求渐进正文
首次翻译 MUST 使用当前整篇 Markdown 的单个流式请求，正文按服务返回顺序渐进显示，MUST NOT 引入分段并行或整篇 JSON 译文包装。重新翻译 MUST 同样渐进展示新正文；既有的加载、取消、旧成功结果回退与最多一次定向修复规则保持有效，MUST NOT 为思考参数策略增加翻译状态机分支。

#### Scenario: 首段到达
- **WHEN** 单请求收到第一段正文
- **THEN** 通过既有预览事件逐步显示译文，不等待全部正文完成，不按并发块重排页面

### Requirement: 不遮挡阅读的翻译进度
手动翻译开始后 MUST 在内容面板顶部立即显示不拦截交互的细意图进度条，等待、流式输出和定向修复期间保持反馈。未知完成比例 MUST NOT 显示为数值百分比。仅成功完成可收尾到终点并淡出；失败或取消 MUST 撤下，保留可阅读内容。进度 MUST 有可访问名称，完成反馈不得抢夺焦点；减少动态效果偏好下 MUST 使用静态反馈。

#### Scenario: 首段前仍可阅读
- **WHEN** 用户点击翻译且首段正文尚未返回
- **THEN** 顶部显示进度，正文保持原文可阅读、选择和滚动，不显示遮挡正文的加载动画

#### Scenario: 重译或终止
- **WHEN** 重译尚未完成，或翻译失败或被取消
- **THEN** 重译首段新正文前保留旧成功译文，之后渐进显示新正文；失败或取消恢复旧译文并撤下进度，不显示成功收尾，正文继续可读

#### Scenario: 缓存和减弱动画
- **WHEN** 初次打开只命中已有译文，或用户启用减少动态效果
- **THEN** 缓存命中不播放手动任务完成动画，减少动态效果时进度采用静态呈现
