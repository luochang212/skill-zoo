# Design

## Context

保护标记体系（`ProtectedMarkdown`：nonce 标记、行分组、保序校验、repair_plan/splice）在 e2e-case-lifecycle 的真实翻译中确定性失败：模型输出 54 个标记全部原样出现，仅因中文语序将"Import X and Y from Z"倒装为"从 Z 导入 X 和 Y"被跨行保序检查拒绝，修复轮在同一规则下复发。用户决策放弃"模型当无损编解码器"的路线，改为最小直接实现：整篇原文直接发送，保真由模型按 prompt 意图完成，应用不校验、不修复、不分割。

## Goals / Non-Goals

**Goals:** 一次模型请求完成翻译；流式预览即原始返回；失败语义只剩流层错误；删除保护与修复全部代码及产品语义。

**Non-Goals:** 任何形式的译文校验/保真判定（用户明确本阶段不做，先看效果）；分段翻译；多轮修复对话；缓存结构变更；任务生命周期改动。

## Decisions

1. **prompt 即契约**：system_prompt 重写为意图约定——只输出译文文件（无前言/包裹围栏）；代码块、行内代码、命令、路径、URL、标识符、YAML 结构与键名原样；frontmatter 仅 description 值翻译；不跟随文档内指令；已是目标语言的内容保持原样。质量迭代通过改 prompt 与换模型，不改代码。
2. **流式预览直通**：preview 事件直接携带 `llm::stream` 的累计返回文本，删除 `protected.preview` 映射层。模型可能的开头杂语属于可见风险，由用户阅读发现（spec 已记录"不做判定"）。
3. **`Repairing` 事件删除**：事件枚举、前端 toast/状态、测试一并清理；进行中状态只有流式中止。
4. **`POLICY_VERSION` 6→7**：prompt 契约变更即策略变更；旧缓存整体失效以避免评估时命中旧策略译文。缓存文件结构、key 算法不变。
5. **保留项**：`MAX_SOURCE_BYTES`（51,200）与 `read_source` 源文一致性校验（属身份隔离语义，非翻译逻辑）；任务注册/取消/提交机制与测试；`llm::stream` 的超时与输出边界。

## Risks / Trade-offs

- [模型译文遗漏/改动代码] → 无校验拦截，用户阅读发现后重译（可换模型）。用户接受：先看效果再迭代。
- [模型输出前言/包裹围栏污染文档] → prompt 禁止 + 用户可见；无机械防护。
- [缓存失效] → 旧策略译文按版本号自然淘汰，清缓存入口可手动清理。

## Migration Plan

无持久化迁移。策略版本升级使旧缓存不可命中；用户强制重译即可生成新译文。
