# skill-content-translation Specification

## Purpose

定义用户在技能详情阅读当前 Markdown 文件时的手动翻译行为：整篇文件零预处理直接发送给模型，翻译由模型理解意图完成，应用只负责任务生命周期、流式展示、缓存与失败恢复，始终保持技能原始文件与编辑草稿独立。

## REMOVED Requirements

### Requirement: 受保护内容保真

**理由**：保护标记体系要求模型在自然翻译的同时字节级保管不透明记号，与目标语言语法天然对抗，产生确定性失败（提案含实证）。保真改为模型按 prompt 意图保留代码与结构，应用不再提供字节级保证，也不再有保真校验、跨行保序与定向修复。

### Requirement: 流式预览容错

**理由**：预览容错仅因保护标记存在而存在。直接发送后预览即模型原始流式输出，无需标记容错。

### Requirement: 流式说明及时展示

**理由**：description 保护标记机制删除后，流式输出即最终形态的渐进到达，无需专门的 description 标记预览逻辑。

### Requirement: 完成与失败判定

**理由**：原要求以保护校验与定向修复定义成功（保真判定）。直接翻译后成功即完整非空输出，不再有任何结构校验，由新的"成功与失败判定"要求替代。

### Requirement: 翻译通知与上下文操作

**理由**：自动修复态（repairing）随保护机制删除，进行中状态只剩流式中止；通知与按钮状态语义由新的"翻译通知与任务反馈"要求替代。

## ADDED Requirements

### Requirement: 成功与失败判定

只有明确正常完成且非空的输出 MUST 被当作成功。截断、拒绝、未知/缺失终止原因、异常断流 MUST 通过 Toast 提示错误并提供工具栏手动重试，MUST NOT 缓存，MUST NOT 自动重试或弹出错误对话框。请求 MUST 有首响应、流空闲与总超时。源文上限 MUST 为 51,200 UTF-8 字节，超过时不请求；输出也须有界。应用 MUST NOT 对译文做结构校验或保真判定：模型返回的完整非空输出即成功，质量问题通过重新翻译迭代。

#### Scenario: 输出截断

- **WHEN** 服务正常结束连接但终止原因是 token 上限
- **THEN** 不显示完整成功，不覆盖旧成功缓存，提示调整模型输出上限后重试

#### Scenario: 译文直接成功

- **WHEN** 模型流式返回完整非空译文并正常结束
- **THEN** 无任何结构校验，直接作为成功结果展示并写入缓存

#### Scenario: 译文遗漏代码等内容

- **WHEN** 模型译文遗漏或改动了代码块、路径等内容
- **THEN** 应用不做判定与拦截，由用户阅读时发现并通过重新翻译（可更换模型）迭代

### Requirement: 翻译通知与任务反馈

技能详情翻译任务失败及翻译配置读写错误 MUST 仅通过 Toast 通知，不渲染正文条幅。任务失败通知 MUST 由共享会话发出，同一终止事件不得重复通知。任务提示 MUST 简短单句，可使用发起时已有技能名称前缀，不增加来源查询或路径、模型、任务编号等附加说明。翻译分体按钮右侧 MUST 在进行中显示中止、终止失败后显示重试，其余状态隐藏。按钮 MUST 仅显示图标，以悬停提示及可访问名称表达动作。编辑、未保存或配置读取未决时重试 MUST 遵守原翻译可用性限制，中止不受编辑模式限制。

#### Scenario: 失败与重试

- **WHEN** 翻译任务终止失败并收到重复失败事件
- **THEN** 仅通知一次错误 Toast，保留可阅读内容，不插入条幅；工具栏显示重试，点击后变为中止

#### Scenario: 中止与成功

- **WHEN** 翻译进行中，或最终成功或手动中止
- **THEN** 进行中只显示中止，不显示重试；成功或中止后隐藏上下文按钮，不将中止作为失败通知

#### Scenario: 配置失败与编辑模式

- **WHEN** 配置读取失败，或正在编辑原文且有在途翻译任务
- **THEN** 配置失败只通过 Toast 告知；编辑模式允许中止在途任务，但禁止对草稿直接重试

#### Scenario: 并行任务的精简反馈

- **WHEN** 用户切换页面后，多个后台翻译任务返回失败
- **THEN** 每条提示使用对应任务发起时的上下文；有现成名称时可简短标识，没有时使用通用短提示，不套用当前页面名称

#### Scenario: 简短且可区分的错误原因

- **WHEN** 翻译任务因额度耗尽、请求受限、认证失败、超时或其他已知错误结束
- **THEN** 原有 Toast 显示对应的应用内本地化简短原因，额度耗尽不提示稍后重试；未知错误回退为通用翻译失败，不显示原始服务商消息、错误码、请求编号或重置时间，不新增条幅或详情面板
## MODIFIED Requirements

### Requirement: 单请求渐进正文

首次翻译 MUST 使用当前整篇 Markdown 原文的单个流式请求，正文按服务返回顺序渐进显示，MUST NOT 引入分段并行或整篇 JSON 译文包装，MUST NOT 在发送前对源文做分块、标记替换或结构改写。重新翻译 MUST 同样渐进展示新正文；既有的加载、取消与旧成功结果回退规则保持有效，MUST NOT 为思考参数策略增加翻译状态机分支。

#### Scenario: 首段到达

- **WHEN** 单请求收到第一段正文
- **THEN** 通过既有预览事件逐步显示译文，不等待全部正文完成，不按并发块重排页面

#### Scenario: 原文直接发送

- **WHEN** 用户对任意 Markdown 或文本内容发起翻译
- **THEN** 发送内容与磁盘源文逐字节一致，不做预处理或格式假设

### Requirement: 不遮挡阅读的翻译进度

手动翻译开始后 MUST 在内容面板顶部立即显示不拦截交互的细意图进度条，等待与流式输出期间保持反馈。未知完成比例 MUST NOT 显示为数值百分比。仅成功完成可收尾到终点并淡出；失败或取消 MUST 撤下，保留可阅读内容。进度 MUST 有可访问名称，完成反馈不得抢夺焦点；减少动态效果偏好下 MUST 使用静态反馈。

#### Scenario: 首段前仍可阅读

- **WHEN** 用户点击翻译且首段正文尚未返回
- **THEN** 顶部显示进度，正文保持原文可阅读、选择和滚动，不显示遮挡正文的加载动画

#### Scenario: 重译或终止

- **WHEN** 重译尚未完成，或翻译失败或被取消
- **THEN** 重译首段新正文前保留旧成功译文，之后渐进显示新正文；失败或取消恢复旧译文并撤下进度，不显示成功收尾，正文继续可读

#### Scenario: 缓存和减弱动画

- **WHEN** 初次打开只命中已有译文，或用户启用减少动态效果
- **THEN** 缓存命中不播放手动任务完成动画，减少动态效果时进度采用静态呈现

### Requirement: 状态与只读展示

下拉 MUST 提供翻译为当前目标语言、语言选择、翻译设置；有结果时提供原文/译文切换与重译，翻译按钮右侧在翻译中显示中止按钮，终止失败后显示重试按钮，其余状态不显示；中止从下拉移至该按钮，按钮只显示图标，悬停提示和可访问名称保留动作文字。初次翻译等待首段正文时 MUST 保留可阅读原文，MUST NOT 用加载图标或空状态替换正文；收到正文后流式显示，允许查看原文；重译等待首段新正文时保留旧成功译文，收到非空预览后 MUST 渐进显示新译文；重译失败或取消 MUST 恢复旧成功译文，只有成功后才替换成功结果与磁盘缓存；用户在生成期间切回原文后，完成 MUST NOT 强制切回译文。译文通过按钮选中态与 tooltip 标识，无常驻模型/AI 文字。编辑或分屏 MUST 使用原文，任何译文 MUST NOT 进入原文草稿或保存路径。当前会话的任务与结果 MUST 保留；重新进入时的正文展示 MUST 遵循「优先显示译文」偏好。自动读取 MUST NOT 发起模型请求。

#### Scenario: 从译文进入编辑

- **WHEN** 用户在译文视图切到编辑
- **THEN** 编辑器仅显示原文，已有草稿保护继续生效
