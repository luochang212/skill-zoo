# Spec Delta

## MODIFIED Requirements

### Requirement: 编辑器保存与草稿保护

技能编辑器的保存完成 MUST 只确认当次提交的内容修订：保存请求在途期间用户继续输入的新内容 MUST 保留为未保存草稿，不得被保存完成或随后的内容重置覆盖。辅助文件（非 SKILL.md）的未保存草稿 MUST 按文件保留，切换其他文件不得丢弃；当存在未保存草稿或未保存的 SKILL.md 修改时，切换技能与关闭详情 MUST 先经用户确认，归档入口 MUST 禁用并说明原因。

#### Scenario: 保存期间输入不被覆盖
- **WHEN** 保存请求在途时用户继续编辑出内容 B，随后保存以提交时的内容 A 成功
- **THEN** 编辑器仍显示 B 且处于未保存状态，不回退为 A

#### Scenario: 无新输入时保存正常收尾
- **WHEN** 保存请求在途期间用户未再输入，保存成功
- **THEN** 编辑器未保存状态清除

#### Scenario: 切换文件保留各文件草稿
- **WHEN** 用户在 README.md 中有未保存草稿，切到 SKILL.md 再切回 README.md
- **THEN** README.md 的草稿原样恢复，且父级收到存在未保存草稿的报告

#### Scenario: 关闭详情前确认未保存内容
- **WHEN** 存在未保存的 SKILL.md 修改或辅助文件草稿时用户关闭详情
- **THEN** 出现确认对话框，用户取消则留在编辑器，确认丢弃则关闭

#### Scenario: 存在未保存内容时归档被禁用
- **WHEN** 存在未保存的 SKILL.md 修改或辅助文件草稿
- **THEN** 归档入口禁用并提示先保存或丢弃修改

#### Scenario: 迟到保存不能确认新会话
- **WHEN** 用户关闭在途保存的详情并打开同一或另一技能，随后旧保存完成
- **THEN** 新会话的草稿及未保存状态不受影响，即使文本相同

#### Scenario: 同目录不同技能隔离辅助草稿
- **WHEN** 用户确认丢弃草稿并切换至 directory 相同但身份不同的技能
- **THEN** 原技能草稿不出现在新技能内，旧请求不能清除新技能草稿

#### Scenario: 还原已保存正文
- **WHEN** 用户把辅助文件改回已保存正文且没有会改变该文件基线的在途保存
- **THEN** 该文件不再被视为未保存，不单独阻止归档或触发离开确认

#### Scenario: 保存期间撤销回旧正文
- **WHEN** 保存内容 A 在途，用户编辑回先前磁盘正文 B，随后 A 保存成功
- **THEN** B 仍作为未保存草稿保留，直到用户保存或明确丢弃
