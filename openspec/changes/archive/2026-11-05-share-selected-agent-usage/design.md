# Design

## Context

Tauri 的 TrayIconEvent 在 Linux 不发出事件，菜单打开回调不能作为所有平台唯一刷新机制。现有统计视图由 React Query 持有结果，原托盘同步扫描固定 agent。

## Goals / Non-Goals

统一已选来源和采集状态；不监听所有日志、不修改调用归因算法、不增加队列框架或新依赖。

## Decisions

- 在 Rust 管理每个 agent 的缓存和异步扫描互斥锁；真正读日志在 spawn_blocking 中进行。成功结果缓存 30 秒；同时排队的请求复用同一次失败，之后显式重试可以立即重扫。各 agent 的锁独立，切换不等待旧来源扫描。
- 使用接口返回 usage/error 快照；读取失败时也携带该 agent 的旧成功结果，首次打开图表不能因前端没有缓存而丢失后台已有结果。
- 前端 Query 缓存只供同来源旧数据展示，显示时向 Rust 检查更新，打开期间每 30 秒检查。Rust 是共享新鲜度和去重的拥有者。
- 两处均从当前 agent 配置判定可用来源，旧来源不可用时优先 Codex，其次首个可统计来源。原设置键保存成功后再切换 UI，保存失败恢复内存设置。托盘每次渲染重新读取当前选择，迟到旧来源扫描只能更新旧缓存。
- 托盘 Enter/Click 触发检查；另有启动后开始、每轮结束后等待 30 秒的串行后台检查，覆盖 Linux 无事件及菜单无法即时更新的情况。周期刷新是尽力而为，扫描耗时可能延后展示，不承诺实时。
- 缺失存储正常为空；目录/文件读取和 SQLite 连接/查询失败明确返回错误。继续跳过坏记录与损坏的压缩日志。

## Risks / Trade-offs

原生菜单动态显示效果依赖平台，未用实际桌面托盘完成跨平台验证；周期刷新保证后续打开可用较新快照。不会为图表读取失败生成零调用统计；同来源旧结果保留并展示错误。完整 CommonMark 或翻译功能不在此变更中。
