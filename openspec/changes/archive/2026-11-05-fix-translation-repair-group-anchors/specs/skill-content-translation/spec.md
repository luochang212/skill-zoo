## MODIFIED Requirements

### Requirement: 完成与失败判定
只有明确正常完成且非空、通过保护校验的输出 MUST 被当作成功。截断、拒绝、未知/缺失终止原因、异常断流 MUST 显示内联错误和手动重试，MUST NOT 缓存；除保真失败后的至多一次定向修复外，MUST NOT 自动重试或弹出错误对话框。定向修复 MUST 在发起前弹出可见提示 Toast，仅重译含损坏标记的源文片段并以完整未受损标记组为锚点确定性拼接，组内译文和合法重排 MUST 原样保留，MUST NOT 用组内单个标记切割；修复规划 MUST 与最终校验共用源文行分组规则，跨组移位或重复标记的所有出现位置 MUST 被损坏区域覆盖，必要时合并相邻损坏范围，修复结果重新整体通过保真校验方可成功；盲目原样重试仍 MUST NOT 自动执行。请求 MUST 有首响应、流空闲与总超时。源文上限 MUST 为 51,200 UTF-8 字节，超过时不请求；输出也须有界。

#### Scenario: 输出截断
- **WHEN** 服务正常结束连接但终止原因是 token 上限
- **THEN** 不显示完整成功，不覆盖旧成功缓存，提示调整模型输出上限后重试

#### Scenario: 漏标记与健康行内重排同时出现
- **WHEN** 元数据标记缺失，但后续完整行内组仅发生合法重排
- **THEN** 仅修复必要的损坏区域，原样保留健康组，拼接不得重复插入其中的标记

#### Scenario: 坏标记跨组出现
- **WHEN** 不完整或重复标记出现在其他组的前后或内部
- **THEN** 修复区域覆盖其全部出现位置，不把含有这些坏标记的范围作为健康锚点保留
