# Design

## Context

调查证据见 docs/research/translation-corruption/README.md。上次只调整 restore，repair_gaps 仍按单标记全序选锚点，造成确定性的重复插入。这是中等严重度的功能失败与 token 浪费，不是原始文件损坏，不需要重构翻译流程。

## Decisions

- 用一个内部分组函数汇总各源文行的输入范围、输出出现范围及是否唯一完整。restore 和 repair_gaps 共同使用它，避免两套顺序规则漂移。
- 修复锚点为整个完好组的输出区间，保留组内已译文字和重排，不以组内单个标记切分。
- 一个候选组只有在其他源文前序/后序组的所有已出现标记也分别位于其前/后时才可做锚点。即使另一组不完整或重复，也统计其全部出现范围；跨组移位会把受影响邻居一起纳入修复，避免在健康区域留下重复项。
- 沿用片段大小控制、单次请求、至多一次定向修复和最终整体校验。修复失败仍不缓存，不猜测丢失元数据。
- 不修改源文/缓存格式。成功缓存原本已通过保真校验，无需为局部修复规划变更失效全部缓存。

## Risks / Trade-offs

跨组移位时可能重译更大区域，但这是覆盖坏标记全部出现位置所必需；正常行内语序重排不会增加修复范围。无法保证模型从不漏标记或每次修复均成功，此变更仅移除应用自行造成的重复。

## Verification

先让与生产函数相连的回归测试失败，再验证重复与移位边界，重放真实响应并发起新的单次定向修复。研究脚本的断言保留为可执行回归，不删除历史失败证据。
