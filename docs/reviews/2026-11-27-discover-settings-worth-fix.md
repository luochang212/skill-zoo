# v1.2.2 发布后回归复核

| 问题 | 证据 | 取舍 |
| --- | --- | --- |
| 子目录在截断后漏项 | Rust 测试用真实缓存 ZIP 和 1 条上限，先确认整仓只返回一项，再验证同一仓库的另一项可通过子目录查询返回。前端测试覆盖粘贴链接后清除筛选，以及整仓和子目录任务的独立进度和取消。 | 大仓库触发，目标 Skill 可能无法通过链接找到。后端按路径分段筛选后再计数和截断，保留仓库级 ZIP 缓存与每个视图的条数上限。 |
| 翻译错误提示不一致 | 全局 mutation 默认会提供反馈。测试用实际 IPC 错误码模拟缓存偏好保存和清理失败，分别验证只出现一次本地化提示。 | 写入失败时的反馈属于操作结果。将处理器放在 mutation 级，覆盖共享的三条保存路径与独立的清理路径。 |
| 全选状态与可见项不符 | RepoDetail 测试注入一个范围外的选中项，修复前全选显示已勾选。 | 用户可误读操作范围。计数与批量切换统一使用当前可安装项。 |
| 全已安装时无分组入口 | RepoDetail 测试在只有已安装项的视图点击分组按钮，修复前找不到入口。 | 状态常见，分组仍有浏览价值，局部调整显示条件。 |
| 合法目录名被裁剪 | Rust URL 解析测试中，修复前 `customSKILL.md` 返回 `custom`。 | 触发较少，但路径被改写会丢失定位。只对 blob 链接处理末尾完整的 `SKILL.md` 文件段。 |
| 校验占位高度为零 | 用 WebKit 渲染两个实际表单，模拟原先的空内容得到 0 px。修复后英文用例在正常和错误状态均为 16 px。 | 属于低影响的布局问题。两处都可以保留同一文案并按状态隐藏，自动跟随文案换行。 |

整仓和子目录按仓库和分支共享勾选状态。清除筛选时保留勾选和分组视图，使用同一分支的整仓查询，并复用有效的查询结果。手动刷新成功后，同一分支的其他视图下次打开时会重新加载。前端回归测试覆盖这两条路径。

缓存刷新会跳过新鲜度检查，并在下载完成后原子替换 ZIP。慢速本地 HTTP 测试复现了刷新期间旧 ZIP 路径消失的问题，并验证修复后旧文件在下载进行中、失败及取消时仍可读取。已有测试覆盖下载成功后的文件替换。

布局测量使用浏览器和模拟 IPC。ZIP 用例使用本地缓存，不依赖 GitHub 网络。
