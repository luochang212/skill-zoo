## 根因

最终 restore 已允许同一源文行内的标记重排；repair_gaps 仍把严格全序的单个标记作为锚点。合法的中文语序使源文的标记 5 移到标记 6–16 之后。规划器将 6–16 错判为待修复，同时在前一个健康输出区间中保留它们。模型按要求修复这些片段后，splice 又插入一次，导致 11 个完好标记重复，最终 restore 按唯一性要求正确拒绝。

这次“漏标记”来自模型，但“修复片段正确仍修复失败”是应用的确定性错误。上次修复遗漏了修复规划器，导致验证与修复使用不同的顺序规则。

## 修复方向

让修复规划和最终验证共享相同的标记分组规则。修复锚点应保留完整、已验证的行内组及其输出区间，不能用组内单个标记切割可重排的译文。保留唯一性、跨组顺序、元数据边界和最多一次修复，不增加并发、重试轮次或新状态。

用户未提供原始两次操作的具体名称，因此本报告不把最近缓存名当成用户确认。已确认并修复下面的程序错误；不宣称解决模型的所有漏标记问题。

## worth-fix 结论与修复

- 属实程度：确定性拼接错误已坐实；“用户任意两篇都必然失败”未被本实验支持，不能扩大结论。
- 定级：中等严重度的翻译功能失败和 token 浪费；最终校验仍拒绝错误结果，原始 skill 文件未被修改，没有坐实原始数据损坏。
- 值得修：真实请求可触发，影响包含漏标记与合法行内重排的翻译；局部修改可以消除不必要失败，收益高于副作用，不需要重构或添加状态。
- 修复：restore 和 repair_gaps 共用 MarkerGroup。修复锚点保留组中最早至最晚标记之间的整个输出区间；组内译文不再被切割。统计坏组中每个标记的全部出现位置，跨组移位或重复会将被影响邻居一并纳入修复，避免坏标记残留在所谓健康范围。
- 安全边界：唯一性、元数据边界和跨组顺序校验保留，仍最多一次修复，失败仍不缓存。健康锚点外与坏元数据相邻的散文前缀可能被一并修复，不承诺整段所有文字都不重译。

验证：将最小复现固化为 Rust 测试，先观察旧实现失败，再观察修复转绿。另以 625 种四槽序列覆盖标记缺失、重复与跨组移位，要求修复后全部标记恰好一次且整体可还原。既有围栏、frontmatter、长片段、缺失/重复及修复测试继续通过。
